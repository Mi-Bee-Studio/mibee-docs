# 能力总览

下表为当前发布版（Lite v0.1.0）的能力清单，以及规划中 Pro 版的增量。所有能力均通过内嵌 Web 配置页（`:9092`）操作，保存后自动生效。

| 能力 | 说明 | Lite v0.1.0 |
|---|---|---|
| 目标检测 | 内置 YOLOv8n 模型（ONNX Runtime CPU 推理），识别画面中的常见目标（人、车、动物等） | ✅ |
| 多目标跟踪 | ByteTrack 跨帧关联，目标有稳定 ID 与轨迹，避免同一目标反复计数 | ✅ |
| 区域入侵 | 在配置页为摄像头划定多边形区域，目标进入即触发事件 | ✅ |
| 越界检测 | 划定边界线，目标跨越方向判定 | ✅ |
| 徘徊检测 | 目标在区域内长时间停留时触发，适合周界、门口等场景 | ✅ |
| 事件与快照 | 结构化事件落库（SQLite/libSQL），每条事件配带框快照 | ✅ |
| NVR 回写 | 分析状态与事件回写 MiBeeNvr：录像列表出现 AI 标记列，AI 事件可在 NVR 中查看 | ✅ |
| Web 配置页 | 填 NVR 地址 + API Key → 拉取摄像头列表 → 选摄像头 → 画规则 → 保存自动重启管线 | ✅ |
| 多摄像头 | 同时分析多路 | Pro |
| GPU 加速 | CUDA / TensorRT 执行提供者 | Pro |
| 历史批量补分析 | 对存量录像批量补跑 | Pro |

## 目标检测

- 模型：**YOLOv8n**，随二进制内置，无需单独下载或配置。
- 推理：ONNX Runtime（CPU），随包提供对应架构的动态库（`libonnxruntime-*.so`），通过 `ORT_DYLIB_PATH` 指定加载。
- 输入：NVR 录像段解码抽帧后送入检测器。

## 多目标跟踪

检测框逐帧交给 **ByteTrack** 跟踪器做跨帧关联：同一目标在连续帧间保持同一 ID，形成轨迹。跟踪的意义在于把「每帧都有框」变成「这个目标从哪来、到哪去、在区域里待了多久」——徘徊检测、越界方向判定都建立在轨迹之上。

## 事件规则

三类规则均可在配置页按摄像头配置（规则名 + 区域顶点）：

| 规则 | 触发条件 | 典型场景 |
|---|---|---|
| 区域入侵 | 目标进入划定区域 | 院子、店铺门口、仓库 |
| 越界 | 目标跨越划定边界线 | 围墙、院门、通道 |
| 徘徊 | 目标在区域内长时间停留 | 周界、门前、ATM |

## 事件与快照

- 事件包含摄像头、时间、规则类型与目标信息，写入本地 SQLite/libSQL 存储。
- 每条事件附带**带检测框的快照**，可在结果中直接看到「是什么触发了这条事件」。

## 回写 MiBeeNvr

分析结果不是留在 Vision 本地就结束了：

- **录像列表 AI 标记**：每段录像的分析状态（处理中 / 完成）直接显示在 NVR 录像列表。
- **AI 事件**：规则触发的事件回写 NVR，可在 NVR 的 AI 事件页查看。
- 详见 [MiBeeNvr 协同](nvr-integration.md)。
